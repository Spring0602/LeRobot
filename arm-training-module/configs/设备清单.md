## 三、历史端口信息

现有 `lerobot-main/README.md` 记录的插线顺序为：

1. 左从臂；
2. 右从臂；
3. 左主臂；
4. 右主臂。

历史命令使用 `/dev/ttyCH341USB*`。若端口编号当时严格按插入顺序递增，可以推测：

| 推测端口 | 推测设备 | 可信度 |
| --- | --- | --- |
| `/dev/ttyCH341USB0` | 左从臂 | 低，仅由插入顺序推测 |
| `/dev/ttyCH341USB1` | 右从臂 | 低，仅由插入顺序推测 |
| `/dev/ttyCH341USB2` | 左主臂 | 低，仅由插入顺序推测 |
| `/dev/ttyCH341USB3` | 右主臂 | 低，仅由插入顺序推测 |

该推测禁止直接用于标定或驱动机械臂，必须在接触实物后逐条验证。

旧的单主从臂配置曾使用主臂 `/dev/ttyCH341USB2`、从臂 `/dev/ttyCH341USB0`，与上述推测部分一致，但不能证明双臂系统的完整对应关系。

## 四、当前 Ubuntu 检测结果

2026-07-19 在未连接机器人硬件的 Ubuntu 虚拟机中执行检查：

- `python -m serial.tools.list_ports -v`：仅发现 `/dev/ttyS0`～`/dev/ttyS31`；
- `/dev/ttyUSB*`：不存在；
- `/dev/ttyACM*`：不存在；
- `/dev/ttyCH341USB*`：不存在；
- `/dev/serial/by-id/`：无记录；
- `/dev/serial/by-path/`：无记录。

结论：虚拟机当前没有识别到机械臂 USB 转串口设备。`ttyS*` 是虚拟串口，不能作为机械臂端口。

## 五、当前缺失的硬件字段

每块控制板仍需补充：

- 当前 `/dev/tty*` 名称；
- USB 厂商 ID（`ID_VENDOR_ID`）；
- USB 产品 ID（`ID_MODEL_ID`）；
- 序列号（`ID_SERIAL`、`ID_SERIAL_SHORT`）；
- 物理 USB 路径（`ID_PATH`）；
- `/dev/serial/by-id` 链接；
- `/dev/serial/by-path` 链接；
- 控制板与 LL/LR/FL/FR 标签的实物对应关系；
- 电机 ID 1～7 的实际连通性；
- 机械臂标定文件及其对应角色。

具体补录流程见 `docs/待硬件任务清单.md`。
