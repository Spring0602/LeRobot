## 第 2 天：环境自动验收

完成内容：

- `verify_environment.py` 支持 `--json-output`；
- 报告包含平台、Python 可执行文件、依赖版本、CUDA、LeRobot 路径、标定缓存、
  数据集目录和输出目录；
- 支持 `--create-runtime-dirs` 创建本地 `datasets/` 与 `outputs/`；
- 软件依赖或必要路径缺失返回退出码 `1`；
- 报告将硬件状态固定标为 `not_checked`，避免把无硬件误报为环境失败。

Ubuntu 命令：

```bash
source "$HOME/lerobot-env/bin/activate"
cd "/mnt/hgfs/engineering_files/arm-training-module"
python scripts/verify_environment.py \
  --create-runtime-dirs \
  --json-output outputs/environment_report.json
```

验收判断：

- `software_ready: true`：软件环境通过；
- `software_ready: false`：查看 `software_failures`；
- `hardware_status: not_checked`：属于预期结果，不表示报错。

## 第 3 天：设备检查与 udev 测试

完成内容：

- 配置错误使用退出码 `1`；
- 无实体设备或实时别名缺失使用退出码 `2`；
- 检查重复序列号和重复别名；
- 检查每条规则都包含 `GROUP="dialout"`、`MODE="0660"` 和 `TAG+="uaccess"`；
- 明确拒绝 `0777`；
- `udevadm` 不存在时返回清晰错误；
- 可区分不存在的别名与断裂软链接；
- `check_devices.py` 在非 Linux 或缺少 pyserial 时给出软件错误，不再产生难懂的导入异常。

离线检查：

```bash
python scripts/device_config.py
```

连接硬件后的在线检查：

```bash
python scripts/device_config.py --live
python scripts/check_devices.py
```

退出码：

| 退出码 | 含义 |
| ---: | --- |
| `0` | 所请求的检查通过 |
| `1` | 软件、配置或工具错误 |
| `2` | 软件可运行，但实体硬件/实时设备仍阻塞 |

## 第 4 天：模拟标定夹具

完成内容：

- 在 `tests/fixtures/calibration_synthetic/` 建立四臂测试夹具；
- 每个文件带有 `"synthetic": true` 和 `fixture_role`；
- 默认标定检查拒绝模拟文件；
- 只有显式使用 `--allow-synthetic` 才能进行离线测试；
- 覆盖缺字段、错误关节顺序、非法 `drive_mode`、损坏 JSON、无活动范围、
  完整备份和未授权部分备份；
- 备份清单增加 `synthetic` 字段。

离线验证模拟夹具：

```bash
python scripts/calibration_files.py \
  --calibration-dir tests/fixtures/calibration_synthetic \
  --allow-synthetic \
  status
```

禁止执行：

```bash
cp tests/fixtures/calibration_synthetic/*.json \
  ../lerobot-main/.cache/calibration/so101_two/
```

模拟文件不含真实零位、方向和活动范围，不能用于真机。
