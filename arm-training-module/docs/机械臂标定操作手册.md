# SO-101 双臂标定操作手册

## 当前结论

目前没有机器人硬件、可信 USB 映射或既有标定文件，不能执行真实标定。本手册完成标定前的软件准备、安全流程、文件校验和备份方案。

## 一、标定的作用

SO-101 手动标定主要确定：

- `homing_offset`：将原始电机位置平移到统一零位；
- `drive_mode`：记录关节方向是否需要反转；
- `start_pos`、`end_pos`：标定动作中读取的参考位置；
- `calib_mode`：六个旋转关节为 `DEGREE`，夹爪为 `LINEAR`；
- `motor_names`：标定数组与七个关节的对应顺序。

标定文件目录由 `So101RobotConfig` 指定为：

```text
lerobot-main/.cache/calibration/so101_two/
```

期望文件：

```text
left_follower.json
right_follower.json
left_leader.json
right_leader.json
```

## 二、标定顺序

现场确认后使用以下顺序：

1. 左从臂 `left_follower`；
2. 右从臂 `right_follower`；
3. 左主臂 `left_leader`；
4. 右主臂 `right_leader`。

每完成一条臂，应立即校验并备份文件，再继续下一条。

## 三、标定前置条件

以下条件必须全部满足：

- 四条臂和 USB 线已贴 LL/LR/FL/FR 标签；
- `/dev/l_left`、`/dev/l_right`、`/dev/f_left`、`/dev/f_right` 已通过实物验证；
- 电机 ID 1～7 已确认且无冲突；
- 用户属于 `dialout`，无需 `sudo` 打开串口；
- 工作台清空，机械臂放置稳定，从臂不悬空承重；
- 操作人理解零位、旋转位和休息位姿；
- 一名观察人能够立即切断机械臂驱动电源；
- 当前有效标定文件已经备份。

任一条件不满足时禁止执行标定。

## 四、只读检查

这些命令不会连接或驱动机械臂：

```bash
source "$HOME/lerobot-env/bin/activate"
cd "/mnt/hgfs/engineering_files/arm-training-module"

python scripts/check_devices.py
python scripts/calibration_files.py status
```

没有硬件或标定文件时，工具返回状态码 `2`，表示前置条件未满足，不是程序崩溃。

## 五、备份标定文件

默认备份到 Ubuntu 用户目录，避免提交设备数据到 Git：

```bash
python scripts/calibration_files.py backup
```

默认目标：

```text
~/lerobot-calibration-backups/<UTC时间>/
```

备份包含四个 JSON 文件和 `manifest.json`；manifest 保存来源、完整性和 SHA-256。缺少任意机械臂文件时，完整备份默认拒绝执行。

只有明确需要保存中间状态时才使用：

```bash
python scripts/calibration_files.py backup --allow-partial
```

## 六、真实标定命令与上游风险

上游命令形式为：

```bash
cd "/mnt/hgfs/engineering_files/lerobot-main"
python lerobot/scripts/control_robot.py \
  --robot.type=so101 \
  --control.type=calibrate \
  --control.arms='["left_follower"]' \
  --robot.cameras='{}'
```

重要：当前上游实现会删除参数指定臂的标定文件，随后连接整个机器人；连接过程会为所有缺少标定文件的机械臂启动手动标定。首次四个文件均不存在时，上述命令仍可能继续要求标定其他三条臂。

因此，在没有实物验证和现场操作人确认前，本项目不提供自动执行包装脚本。取得硬件后，应先在隔离的一条臂配置上验证流程，或修改上游逻辑使连接阶段只包含目标臂，再执行逐臂标定。

## 七、手动标定过程

上游流程会依次要求：

1. 将机械臂移动到零位并读取位置；
2. 将各关节移动到指定旋转位，用于判断方向；
3. 将机械臂移动到休息位；
4. 生成 homing offset、drive mode 和标定模式；
5. 保存对应 JSON 文件。

操作过程中应缓慢手动移动，不强行越过机械阻力，不依赖猜测的左右或主从映射。

## 八、急停与断电流程

### 标定前

1. 明确机械臂驱动电源开关或插头位置；
2. 观察人将手放在可立即断电的位置；
3. 确认切断的是机械臂驱动电源，而不是仅拔 USB；
4. 清除机械臂运动范围内的人员和物品。

### 出现异常时

1. 操作人停止移动机械臂；
2. 观察人立即切断驱动电源；
3. 再按 `Ctrl+C` 终止程序；
4. 不把拔 USB 当作急停，因为断开通信不一定切断舵机供电；
5. 记录异常关节、位姿、声音、端口和终端输出；
6. 原因未确认前禁止重新上电。

### 恢复前

1. 检查机械干涉、线缆拉扯和舵机温度；
2. 检查端口映射是否错误；
3. 检查标定文件是否为当前机械臂生成；
4. 将机械臂人工放回安全位；
5. 单臂、低风险方式恢复，不直接启动双臂遥操作。

## 九、标定后验收

每条臂必须完成：

- 标定 JSON 通过 `calibration_files.py status`；
- 文件名与机械臂标签一致；
- 备份 manifest 中存在对应 SHA-256；
- 七个关节方向正确；
- 零位附近无突然跳变；
- 小幅动作不撞限位、不拉扯线缆；
- 安全活动范围已填写到 `configs/关节活动范围记录.md`。

只有四条臂全部通过，才能进入第 6 天双臂遥操作验证。
