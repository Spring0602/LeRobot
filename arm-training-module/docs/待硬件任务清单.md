# 待硬件任务清单

## 说明

当前 Ubuntu 虚拟机从未连接过机器人。现已从原 Jetson 的 udev 规则恢复四块控制板
唯一编号和逻辑角色映射，但机械臂与线缆没有实体标签，恢复结果也尚未在当前系统
重插验证。因此，下列现场任务仍必须等能够接触 SO-101 实物后完成。

所有操作应先激活环境：

```bash
source "$HOME/lerobot-env/bin/activate"
cd "/mnt/hgfs/engineering_files/lerobot-main"
```

## 任务 1：确认和标记四条机械臂

状态：部分完成。序列号与逻辑角色已恢复；已确认 USB 线没有标签，现场补贴标签仍阻塞。

操作步骤：

1. 根据机械安装位置和操作者确认主臂、从臂及左右方向；
2. 给机械臂本体和对应 USB 数据线同时贴标签：`LL`、`LR`、`FL`、`FR`；
3. 拍摄包含机械臂与线缆标签的全景照片；
4. 将标签、照片文件名和现场确认人记录到 `configs/设备清单.md`。

验收标准：任意一根 USB 线都能在不通电运行程序的情况下确定所属机械臂。

## 任务 2：将控制板 USB 转交给 Ubuntu 虚拟机

状态：阻塞，缺少实物 USB 设备。

操作步骤：

1. 先只连接一条机械臂控制板；
2. 在 VMware 的“虚拟机 → 可移动设备”中找到 CH340/CH341、USB Serial 或对应控制板；
3. 选择“连接（断开与主机的连接）”；
4. 在 Ubuntu 执行：

   ```bash
   lsusb
   sudo dmesg | tail -n 30
   python -m serial.tools.list_ports -v
   ```

5. 确认出现 `/dev/ttyUSB*`、`/dev/ttyACM*` 或 `/dev/ttyCH341USB*`；
6. 对另外三块控制板重复操作。

验收标准：Ubuntu 同时识别四个 USB 串口，且没有把 `/dev/ttyS*` 误认为机械臂。

## 任务 3：建立临时串口与机械臂对应表

状态：部分完成。已从原 udev 规则恢复稳定映射；临时端口观察仍需实物。

操作步骤：

1. 四条臂均连接后运行：

   ```bash
   python lerobot/scripts/find_motors_bus_port.py
   ```

2. 按程序提示，每次只拔掉一条已贴标签的机械臂 USB 数据线；
3. 记录程序显示的消失端口；
4. 立即重新插回该设备，再识别下一条；
5. 将结果填写到 `configs/设备清单.md` 的“临时串口”列；
6. 交换 USB 插入顺序并复查，确认临时编号可能变化。

验收标准：四条机械臂均有明确的临时串口记录，且识别过程每次只有一个端口发生变化。

## 任务 4：采集 USB 唯一属性

状态：离线完成，现场复验阻塞。

已恢复并写入 `configs/so101_devices.json`：

```text
5AAF288040 -> /dev/f_left
5A7C119017 -> /dev/f_right
5AB0158432 -> /dev/l_left
5AAF288007 -> /dev/l_right
USB VID:PID = 1a86:55d3
```

不要直接复制原规则中的 `MODE:="0777"`。项目已生成最小权限规则
`configs/99-so101.rules`，安装和复验命令为：

```bash
cd "/mnt/hgfs/engineering_files/arm-training-module"
python scripts/device_config.py
chmod +x scripts/install_udev_rules.sh
./scripts/install_udev_rules.sh
# 重新插入四块控制板
python scripts/device_config.py --live
```

只有 `--live` 对四个别名均显示 `[OK]`，才算完成现场验收。

对每个已确认端口执行：

```bash
udevadm info --query=property --name=/dev/ttyUSB0
```

将端口替换为实际名称，并记录：

```text
ID_VENDOR_ID
ID_MODEL_ID
ID_SERIAL
ID_SERIAL_SHORT
ID_PATH
```

同时记录稳定链接：

```bash
ls -l /dev/serial/by-id/ 2>/dev/null
ls -l /dev/serial/by-path/ 2>/dev/null
```

判断规则：

- 四块板具有不同 `ID_SERIAL_SHORT`：优先按序列号建立 udev 规则；
- 序列号相同或为空：使用 `ID_PATH` 按固定物理 USB 接口映射；
- `by-id` 已唯一且稳定：可直接在配置中使用对应链接。

验收标准：每个 LL/LR/FL/FR 标签至少有一种可重复识别的唯一属性。

## 任务 5：确认串口访问权限

状态：可检查用户组，但最终端口权限需实物设备出现后确认。

操作步骤：

```bash
groups
ls -l /dev/ttyUSB0
```

如果用户不属于 `dialout`：

```bash
sudo usermod -aG dialout wang
```

注销并重新登录后再次执行 `groups`。不要长期使用 `chmod 777`。

验收标准：用户 `wang` 属于 `dialout`，无需 `sudo` 即可打开四个机械臂串口。

## 任务 6：核验电机 ID 与关节对应关系

状态：阻塞，缺少实物；属于高风险操作。

操作步骤：

1. 确认四条机械臂的串口映射无误；
2. 将机械臂放到稳定位置，从臂不得悬空承重；
3. 先只连接一条臂，读取 ID 1～7 的当前位置；
4. 逐关节做小幅、安全动作，确认 ID 与关节名称对应；
5. 记录异常、缺失或重复 ID；
6. 只有在单个电机与总线隔离后，才允许使用 `configure_motor.py` 修改 ID 或波特率。

禁止在七个电机全部连接时盲目运行电机配置脚本。

验收标准：四条臂均确认 ID 1～7 可通信，并与代码中的七个关节名称一致。

## 任务 7：建立稳定 udev 映射

状态：规则已完成，现场重插与角色复验阻塞。

目标映射：

```text
左主臂 → /dev/l_left
右主臂 → /dev/l_right
左从臂 → /dev/f_left
右从臂 → /dev/f_right
```

操作步骤：

1. 先运行 `python scripts/device_config.py` 校验项目内映射；
2. 运行 `./scripts/install_udev_rules.sh` 安装 `/etc/udev/rules.d/99-so101.rules`；
3. 重新加载规则（安装脚本已自动执行）：

   ```bash
   sudo udevadm control --reload-rules
   sudo udevadm trigger
   ```

4. 逐个重插设备；
5. 运行 `python scripts/device_config.py --live` 检查链接、序列号和权限；
6. 也可人工检查链接：

   ```bash
   ls -l /dev/l_left /dev/l_right /dev/f_left /dev/f_right
   ```

7. 重启并改变插线顺序，再次检查映射。

验收标准：无论重启或改变插入顺序，四个稳定名称始终指向正确机械臂。

## 任务 8：获取并备份标定文件

状态：已确认原目录曾存在，但未取得目录内具体 JSON；备份仍阻塞。

操作步骤：

1. 先向原项目负责人询问是否保留 `.cache/calibration/so101_two`；
2. 若取得旧文件，记录每个文件对应的机械臂和生成日期；
3. 串口映射确认后，再判断旧标定是否适用于当前实物；
4. 旧标定无法确认时，按从臂到主臂、单臂到双臂重新标定；
5. 将有效标定文件备份到安全位置，但不要公开设备私有信息。

验收标准：四条臂均有角色明确、来源可追溯且经过实物验证的标定文件。

## 任务 9：执行四臂标定和活动范围测量

状态：阻塞，缺少实物、可信端口映射和现场急停条件；属于第 5 天硬件工作。

操作步骤：

1. 阅读 `docs/机械臂标定操作手册.md`；
2. 完成设备贴标、稳定端口、电机 ID 和断电流程检查；
3. 按左从、右从、左主、右主顺序逐臂标定；
4. 每完成一条臂，运行 `python scripts/calibration_files.py status`；
5. 运行 `python scripts/calibration_files.py backup --allow-partial` 保存中间状态；
6. 四条臂完成后运行完整备份；
7. 逐关节、低速、小步进测量安全范围，填写 `configs/关节活动范围记录.md`；
8. 进行方向、零位、机械干涉和线缆拉扯检查。

验收标准：四个标定文件有效并已备份，28 个关节记录项均经过实物验证，无反向运动、突然跳变或撞限位。

## 任务 10：第 6 天遥操作现场验收

状态：软件前置检查已准备；缺少实物、标定文件和现场断电条件。

操作步骤：

1. 先完成任务 1～9，不允许跳过端口、标定和安全检查；
2. 运行 `python scripts/stage1_preflight.py` 保存检查结果；
3. 清空工作区，安排一人操作、一人负责物理断电；
4. 使用项目历史命令先关闭相机、只做单主从臂低速验证；
5. 逐关节确认方向、跟随、夹爪、抖动和线缆状态；
6. 单臂稳定后再测试双臂；
7. 连续运行 10 分钟，记录串口中断、跟随误差和异常。

历史中出现过以下命令，但不可在前置条件未满足时直接执行：

```bash
python lerobot/scripts/control_robot.py \
  --robot.type=so101 \
  --control.type=teleoperate \
  --robot.cameras='{}'
```

验收标准：连续遥操作 10 分钟，无串口中断、异常抖动、反向运动或明显跟随错误。

## 任务 11：第 7 天相机现场验收

状态：枚举流程已准备；相机型号、唯一编号、视角和画面质量未知。

操作步骤：

1. 执行 `v4l2-ctl --list-devices` 和 `ls -l /dev/v4l/by-id /dev/v4l/by-path`；
2. 每次遮挡一个镜头，确认全局、左腕和右腕实际对应关系；
3. 记录每台相机的型号、序列号、稳定链接、分辨率和帧率；
4. 不直接把历史索引 `0/2/4` 当作稳定映射；
5. 遥操作时检查延迟、遮挡、曝光、亮度和掉帧；
6. 将结果补充到 `configs/设备清单.md`。

验收标准：重启后仍能按稳定标识打开正确视角，且遥操作时画面稳定可用。
